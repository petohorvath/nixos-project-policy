# Proposed standards and verification

This review document translates the [normalization decisions](normalization-design.md) and existing global skills into a portable policy outline. The requirements, coding/documentation baseline, and formatter coverage come from answered interview questions. Q37 limits current preparation to the policy repository; member migrations remain deferred.

## Coding and documentation baseline

Q35 adopts the coding and documentation baseline below for new and changed first-party material. Architecture and prose remain review criteria; existing lint findings are handled under Q21. Q36 requires root formatting for all applicable first-party Nix, Go, shell, Markdown, YAML, and JSON files, with project-owned configuration and the agreed exclusions. Framework preferences, additional commit-title length/casing rules, generated documentation, TDD, and universal coverage floors do not become mandatory gates through this decision.

| ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Preserve intentionally pure library interfaces.                                                           |

An acyclic flake graph alone does not establish correct internal architecture.                                                                                       |

Do not require a treefmt dependency merely to share an interface.                                                              |

The Nix skill says to prefer flake-parts; it does not mandate migrating every existing flake. None of the inspected Nix, documentation, Markdown, agent-writing, or commit-message skills requires nixd or generated project documentation. Nil is already selected, and project documentation generation remains optional.

## Scope and project-specific contracts

The final policy must state which rules cover all first-party files and which apply only to new or changed material. Vendored code, generated output, intentional lint suppressions, and technically required tool replacements need explicit treatment. Q21 already requires fixing real lint findings before those gates become mandatory.

Each project should point to its public interface, supported runtime and Nix constraints, development commands, test commands, and specialized prerequisites. Existing project commitments, such as shields' Nix/plugin compatibility and wanwatch's coverage requirements, must be preserved or changed through an explicit review; their existence does not make them universal family rules.

Global skill files are evidence used during this design session. The eventual policy repository must contain self-contained, linkable normative text that contributors can understand without those files. The external checker's version, active rules, project exceptions, and update-batch state must be identifiable in its results.

## Completion evidence to require in the rollout plan

- Development entrypoints and required tools work on both supported Linux architectures.
- All applicable lock graphs match the approved shared pins, with tracked rollout differences resolved.
- Default local checks do not execute VM tests, while the applicable VM gates run successfully on suitable CI hosts.
- Required external checks and human merge controls are configured and verified on a pilot PR before wider rollout.
- README and contribution entrypoints point to accurate local instructions and the approved shared rules.
- Known lint findings, stale hooks, broken local links, and conflicting release-history wording are resolved within the relevant migration PRs.

This evidence list describes eventual family adoption. All seven interview rounds are answered: Q35 adopts the coding/documentation baseline, Q36 adopts all applicable formatter languages, and Q37 limits current preparation to the policy repository. Member migration selection and order remain deferred in the [rollout scope](normalization-rollout.md).
